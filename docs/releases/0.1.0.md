# passgen 0.1.0 release notes

Released: 24 September 2026.

passgen 0.1.0 is the initial release of the offline memorable-password generator. It includes the Python CLI, Python desktop UI, Python library API, and static browser app.

## Highlights

- Secure random generation throughout: Python uses `secrets`; the browser uses Web Crypto `crypto.getRandomValues()` with rejection sampling and no predictable fallback.
- Static browser app with no backend, analytics, persistent browser storage, or password upload.
- Clear browser modes: **Wordlist** and **Name + Place + Thing**.
- Separate **Generate password** and **Copy** actions.
- Active browser passwords show a character count and countdown, then move to masked Recent passwords after 10, 30, or 60 seconds.
- Recent passwords are capped at the latest 10 entries and clear on refresh.
- Browser and desktop UIs use plain-text `names.txt`, `places.txt`, and `things.txt` lists; TOML is absent from both UIs.
- CLI keeps legacy TOML compatibility while also supporting TXT overrides.

## Generation behavior

Wordlist mode uses bundled `wordlist.txt`, with 10,754 normalized unique words from EFF and SCOWL sources. Dictionary generation defaults to at least three requested words and supports 3-128 requested words, subject to the selected character range.

Name + Place + Thing mode selects one entry from each configured set. The browser starts with visible packaged defaults and lets users paste, edit, or replace each category with a local TXT file. Edited browser text must be applied before it is used, and editing a list does not switch generation modes.

Passwords are generated against a final output range. The default is 16-64 characters, with a hard ceiling of 128. Generation fails clearly rather than truncating output, dropping requested words, or silently relaxing settings.

Mixed case, numbers, and symbols are enabled by default. Lookalike substitutions are optional and off by default. Easy-to-type mode can avoid introducing `0`, `1`, `I`, and `O`.

## Interfaces

The Python CLI supports dictionary mode by default, configured sets through TOML or TXT files, `--min-length`, `--max-length`, `--words`, requirement toggles, substitutions, and easy-to-type mode.

The desktop UI starts with packaged TXT defaults, lets users choose dictionary mode or configured sets, and can replace Names, Places, and Things with local TXT files. It does not read TOML.

The browser app has visible Wordlist and Name + Place + Thing choices near the main generation flow. It keeps policy controls temporary, does not write to localStorage or sessionStorage, and resets active/recent passwords plus imported/edited lists on refresh.

## Security notes

Generation is local. Browser state is held in page memory only. Masking Recent passwords does not securely erase them from memory, and copied passwords may remain in OS or browser clipboard history.

The packaged Name + Place + Thing defaults are public demonstration data. Replace them for real use. Small or predictable personal lists can be guessed even with substitutions, casing, symbols, or length constraints.

Three requested words favors usability and is not a universal strength recommendation. For sensitive accounts, prefer more dictionary words or wider fitting length ranges when the destination site allows them.

This initial release has not undergone an independent security audit.

## Validation

The 0.1.0 release was validated with:

- `poetry run pytest`
- `poetry run ruff check .`
- `npm test`
- `npm run build`
- `npm run test:browser`
- Python wheel packaging check

Firefox and Safari behavior still need explicit verification before claiming full cross-browser support.

## Compatibility

- Python 3.11 or newer.
- Node.js 22.12 or newer for browser development and builds.
- Browser app requires localhost or HTTPS for module loading and clipboard APIs.
